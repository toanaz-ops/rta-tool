**What happened (lane L6b, station 1, 2026-09-06).** The lane opened from the
G14/G15/G20 rows of `docs/dsp/2026-08-28-competitive-parity.md`. The research
agents found: REW's averages are all unweighted (G15's "REW Pro" attribution
false); SysTune "SSA" is *Spectrally Selective Accumulation*, a temporal
noise filter, not "Smoothed Spatial Averaging" (the brief had expanded an
acronym from its sound); and no reachable L-Acoustics M1 document defines any
bad-capture criterion — six trade articles repeat one press release (G20's
"automatic bad-capture discard" is unverified). A fourth premise the brief
carried from an earlier session — "Open Sound Meter has no remote API" — was
also false. The parity rows were corrected in place with the date and source.

**Why.** The parity table was written in one market sweep from product pages
and marketing copy, which is what a parity table is for. It is a list of
*claims about competitors*, and a claim about a competitor is exactly as
reliable as the page it came from. Building to it without re-reading the
source turns a marketing sentence into a design requirement.

**How to apply.** When a lane's brief cites the parity table, station 1's first
deliverable is a "corrections to the brief" section, before any finding.
Attribute each feature to the product's own manual or code, and mark what
only press coverage attests as UNVERIFIED. Then fix the parity row so the next
lane does not inherit the error. Related: [[a-public-issue-has-a-date-too]]
(the same failure for an issue tracker).
