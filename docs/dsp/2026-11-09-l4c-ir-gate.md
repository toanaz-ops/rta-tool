## 2. Literature

- **The resolution of a T-long window is 1/T.** A gate of length T keeps
  information about the frequency response only above roughly 1/T: below it
  the gate truncates the system's own low-frequency response, not just the
  reflections. This is the standard gated-measurement rule ("the first
  reflection sets the gate, the gate sets the lowest valid frequency"; e.g.
  D'Appolito, *Testing Loudspeakers*, 1998 -- cited from memory, chapter not
  re-checked). This number is the lane's one honest output besides the curve.
- **Truncation is multiplication in time, convolution in frequency** (Harris
  1978). A rectangular cut at a non-zero sample smears ripple across the
  band; a raised-cosine (Tukey) taper trades a wider main lobe for far lower
  sidelobes. The taper must reach zero BEFORE the first reflection, or the
  reflection leaks back in at reduced gain.
- The gate must not move the time origin: `IrSpectrum.cpp:59-73` removes the
  lead-in's linear phase so phase reads referenced to the arrival. A gate that
  re-cuts the IR must go through the same routine or re-derive the same
  rotation; re-deriving it is how a 5 ms bias would come back.

## 3. How other tools do it (code where it is open)

- **pyfar** (`pyfar.dsp.time_window`, open source): `interval` of 2 or 4
  times; with 4 values the window is fade-in / flat / fade-out, each fade a
  half of the chosen scipy window (default `hann`). `shape='right'` leaves the
  start untouched and fades only the end. Our gate is this 4-point form.
- **REW** (closed, documented behaviour): separate *left* and *right* IR
  windows, each with its own type (rectangular, Hann, Tukey 0.25..0.75, ...);
  the right window is set to end before the first reflection for a
  quasi-anechoic view; separately offers a frequency-dependent window (FDW,
  width in cycles).
- **ARTA / HOLMImpulse / CLIO** (closed): a draggable gate marker on the IR
  plot, half-window on the right edge, and the plot of the gated response
  annotated with its lowest valid frequency.
- **Open Sound Meter, Friture**: no IR gate (dual-FFT / RTA only). They are
  where the live transfer comes from, not this feature.

Disagreement worth recording: REW defaults to a Hann *left* window of
~125 ms (room view) while ARTA gates a few ms (anechoic view). Both are
correct for their question; ours is the anechoic question (G25), so the
default follows ARTA, not REW.

## 4. Candidates

**A. Fixed gate, 4-point Tukey (fade-in, flat, fade-out), operator drags start
and end.** The obvious one.
*Against it:* (1) the low-frequency limit is a cliff, not a slope -- a
response at 1.2/T is barely more trustworthy than at 0.8/T, and the curve
will be drawn there anyway; (2) the operator must find the first reflection
on an ETC by eye, and a dragged marker invites ending the gate ON the
reflection; (3) a taper shortens the effective window, so 1/T over-states
what is resolved.
*Answers:* (1) is the published convention every surveyed tool reports; we
report it, do not hide the curve below it, and mark it on the readout.
(2) The ETC plot shows the envelope in dB, where a reflection 10-20 dB down is
visible; the readout names the reflection the gate end would include. Not
automated here (reflection detection is a separate claim with its own
fixtures). (3) We report 1/T_flat+fade-out/2, i.e. the length to the fade-out's
half-amplitude point, not the full T: a conservative choice that a test pins.

**B. Frequency-dependent window (REW FDW, N cycles per frequency).**
Better for the room view, wrong for G25: it is not a gate (the window grows
at low frequency, so it never removes reflections there) and costs a
per-bin transform (a constant-Q / per-band recompute, minutes of design and
a second validation campaign). Rejected for this lane; it is the right tool
for a "smoothed in-room" view if one is ever asked for.

**C. Reuse the MTW engine as the gate.** `MtwEngine` already applies several
time windows per band to the live dual-FFT stream. Rejected: it windows
stationary-noise blocks, not a deconvolved IR, and has no notion of an
arrival or a first reflection. Bending it to IRs would put an IR concept
into the live transfer path, which is exactly the coupling L3 avoided.

**Chosen: A**, with the effective-length rule in (3).

## 5. Decisions (each with what the rejected option would have cost)

1. **Core function, pure.** `rta::ir::gateSpectrum(const Deconvolution&, const
   GateSpec&)` in `core/include/rta/ir/IrGate.h`: builds the gated copy of the
   IR and hands it to `analyseSpectrum`, so the lead-in phase rotation is the
   existing one. *Rejected:* gating inside `app/` -- untestable on CI without
   JUCE, and a second copy of the phase rotation.
2. **Times are relative to the arrival**, in milliseconds: `startMs` (default
   -1.0, i.e. 1 ms before the peak) and `endMs` (default +10.0). The flat part
   runs from start+fadeIn to end-fadeOut. Fade-in 0.5 ms half-Hann; fade-out
   25 % of the gate length, half-Hann. *Rejected:* absolute sample indices --
   every operator reading is "ms after the direct sound".
3. **Lowest valid frequency** `fMin = 1 / (end - start - fadeOut/2)` seconds.
   Reported in the readout and in the stored trace's meta `window` string
   ("gate -1.0..10.0 ms, valid above 104 Hz"; 1/(11 - 1.375) ms = 103.9 Hz, printed rounded UP). **No session-schema change**:
   `CaptureMeta` has no trusted-range field and adding one is persisted state;
   coherence is NOT faked to 0 below fMin (that would make the TRANSFER
   coherence blanking lie about a measurement quantity).
4. **Refusals, not clamps** (the shipped list is longer -- see §6): start >= end, a gate shorter than its own fades,
   a start before the IR's first sample or an end past its last return a
   refusal with the offending value, never a silently moved marker.
5. **Operator path**: a new pane `IR` (eighth selector cell -- RT60 was already seventh,
   `PaneView::Ir`, persisted as the string `ir`; old sessions never contain
   it, an old build opening a new session falls back like any unknown view).
   It shows: IR picker (same `IrStore` choices as RT60), ETC (dB envelope vs
   ms after arrival), two draggable gate markers, the gated magnitude, and a
   `STORE GATED` button that adds the gated response to the `TraceLibrary`
   (visible in TRANSFER like any stored trace). *Rejected:* gating inside the
   RT60 pane -- RT60 wants the whole decay; a gate there would be a control
   that does nothing to the RT60 numbers next to it.
